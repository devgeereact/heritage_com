# Test Strategy

This file owns how HeritOS is checked: the risk priorities, the commands and their latest results, the coverage plan, and the baseline audit record of 10 October 2026. Audit evidence for each area lives in the root [qa/](../qa/) files; the launch verification matrix is in [LAUNCH-CHECKLIST.md](../qa/LAUNCH-CHECKLIST.md). Results use PASS, FAIL, PARTIAL, NOT APPLICABLE, NOT TESTED or BLOCKED.

## Risk priorities

- **Critical user journeys:** enquiry to job conversion, measurements and snapshots, appointments, payments, customer access ([USER-JOURNEYS.md](USER-JOURNEYS.md)).
- **Security and data-loss risks:** cross-customer access (A03), stored script (A04), lost payments (A05), development writing to production (A01), unknown deployed endpoints (A02), backups never restored (A20).
- **Business-rule failures:** double bookings, changed measurements on an existing job, wrong totals ([BUSINESS-RULES.md](BUSINESS-RULES.md)).
- **Supported environments:** local staging for all functional testing; production only for post-release smoke checks with designated test records. Browsers and devices at the widths in [ACCESSIBILITY.md](ACCESSIBILITY.md).

Frontend test notes (18 October 2026). The suite runs in jsdom, not a real browser, so it proves behaviour (what is sent, shown, stored and focused) and says nothing about layout, colour or touch. It does not cover the admin screens beyond sign-in, the shop checkout, the customer portal or the service worker; those stay NOT TESTED until a browser journey is run. Tests import `describe`, `it`, `expect` and `vi` from `vitest` because the ESLint config declares no test globals. On Node 25 and later the shared setup (`src/__tests__/setup.js`) restores jsdom's `localStorage`, which Node's own experimental one would otherwise hide. The suite found that `AuthProvider` read the session cookie with an unguarded `JSON.parse` (`src/context/useAuthContext.jsx`, `getSession`), so a cookie that was not valid JSON blanked the app (the provider sits above the error boundary). Since 18 October 2026 a cookie that is not a JSON object is removed and the app starts signed out; the test that was skipped now runs, with a second for valid JSON that is not a profile. The suite also found that `safeHtml.js` and `richText.js` accepted a link starting `/\`, which browsers read as `//`; both now refuse it and the tests cover it.
