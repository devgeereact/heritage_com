# Audit and plan drift

## Baseline and verdict

Production confidence: PARTIAL. The application has a real PHP API client, staff authentication, tailoring records, saved measurements, customer records, enquiry handling, retail orders and CMS content. It also carries extensive retail, marketing and template surfaces. Treat “all modules built” in CLAUDE.md as a historical implementation claim, not a launch certificate.

Inspection is risk-based across the whole repository structure, route catalogue, API catalogue, schemas, public pages, central integration code and selected critical implementations. It is not a claim that every line of 774 tracked files has been reviewed.

Verification pass, 10 October 2026: every finding was re-checked against source by file and line. Rows marked Verified quote the code. A06 was downgraded (unique keys exist), A03 and A13 were upgraded, and A21 to A24 are new. Confidence labels follow the key in READ-ME-FIRST.md.

## Where the old plan drifted

The old checklist prioritises product variants, cart, coupons, international shipping and eight-role commerce while measurements and fittings are P1. Your current business requires the reverse. Its Laravel/TypeScript paths are also different from this PHP/JavaScript repository, already acknowledged by docs/README.md.

CLAUDE.md calls all 14 modules live, while the deployment manifest includes only nine PHP files and no runtime proof was available here. Documentation also describes 14 modules/182 features while docs/features.md enumerates 18 areas. These are incompatible completeness signals, not useful progress metrics.

There are two HeritOS.html files with different file sizes, and several overlapping rule/memory entry points. Neither should become the approved plan merely because it is older. The new plan supersedes their priorities only after approval; the repository source remains evidence of implementation.

The design has accumulated brand flourishes, carousels, animated numbers and decorative fabric tiles. The requested Tesla reference changes the direction towards restraint and real imagery. Approval should explicitly replace the old decorative rules, while preserving functional clarity and the Herit identity.

Two further kinds of drift were found in the verification pass. First, documented brand rules that never reached the code: the Tack Stitch edge (A23) is described as the signature treatment but does not exist, and public and admin styles keep separate token sets. Second, launch claims that were invented: the team, statistics, testimonials and offers on the home page are confirmed by the owner as not real (A07). Documentation and website both described a business that does not match the owner's.

## Immediate interpretation

Do not discard the project or rebuild all features. Keep the functional core, close unsafe data paths, connect the missing journeys and hide unused complexity. A focused product can still hold substantial records without making its owner manage a retail enterprise dashboard every morning.
